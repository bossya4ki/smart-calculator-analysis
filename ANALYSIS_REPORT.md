# Статический анализ умного калькулятора

## Исходные данные и окружение

В папке задания находился фрагмент calculator.py в Word. Для анализа до правок использован этот фрагмент, а operations.py и main.py восстановлены в составе проекта. Python 3.12.14. Версии всех инструментов закреплены в requirements.txt.

Flake8 проверяет стиль, неиспользуемые имена и сложность. Совместно с Black задана длина строки 100 символов. Правила E203 и W503 отключены для совместимости форматирования. Порог цикломатической сложности равен 10. Pylint проверяет структуру и качество кода. В его конфигурации допускается минимум один публичный метод. Bandit ищет опасные конструкции, MyPy проверяет типы, Black проверяет форматирование. autopep8 использован для промежуточного исправления стиля.

## Проблемы и исправления

1. **Выполнение выражений через eval.** При обработке непроверенного ввода этот вызов может выполнить произвольный Python-код. Функция удалена. Поддерживаемые операции определяет явная таблица диспетчеризации.
2. **Кодировка файлов.** Без encoding результат зависит от локали компьютера. История теперь читается и сохраняется в UTF-8.
3. **Обработка деления на ноль.** Ошибка прерывала расчёт возвратом None и выводом в консоль из модели. Теперь операция возбуждает ZeroDivisionError, а CLI выводит сообщение и возвращает код 1.
4. **Неизвестная операция.** Для неверного знака модель сообщает ValueError. Консольный парсер дополнительно ограничивает ввод четырьмя операциями.
5. **Дублирование проверки файла.** В исходном фрагменте существование файла проверялось отдельно до открытия. Теперь FileNotFoundError обрабатывается при чтении, а остальные ошибки ввода-вывода получает вызывающий код.
6. **Неиспользуемая функция.** Демонстрационная unused_function удалена, поскольку она не участвует в работе калькулятора.
7. **Документация и стиль.** Добавлены строки документации, типы и правила форматирования. Форматирование отдельно проверено Black.

## Контроль исправлений

Сначала выполнен анализ исходника, затем отдельно обработано форматирование через autopep8 и повторён Flake8. После рефакторинга запущены все пять проверок и проверены сценарии 5 ÷ 2, 3 × 4 и деление на ноль. Успешные операции попадают в историю. Неуспешная операция историю не меняет.

В автоматизации предусмотрены точечные исключения Bandit B404 и B603 для вызова анализаторов из analyze.py. Запускается текущий Python с фиксированными модулями, список файлов проверяется, оболочка не используется. В прикладных модулях исключений нет.

Настройка GitHub Actions находится в .github/workflows/analysis.yml. Она устанавливает закреплённые зависимости и выполняет python analyze.py при push и pull request. Локальные запуски выполнены. Запуск на сервере требует публикации проекта.
